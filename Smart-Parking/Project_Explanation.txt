SMART PARKING SPACE ALLOCATION SYSTEM

1. Introduction

The Smart Parking Space Allocation System assigns a suitable parking space to an arriving vehicle. The system
considers vehicle type, parking requirement, space type, availability and distance. It reports a successful allocation
or explains that no suitable space is available.

2. Representation of parking spaces

Space  Type        Initial status    Distance
P1     Compact     Occupied            2
P2     Compact     Available           4
P3     Regular     Available           3
P4     Reserved    Available           5
P5     Large       Available           7
P6     Accessible  Available           2
P7     Regular     Occupied            6
P8     Large       Available           4
P9     Compact     Available           1
P10    Accessible  Available           3

3. Facts, predicates and rules

Facts: The space facts store each space ID, its type, its current status and its distance. Predicates: Predicates
such as candidate, compatible and find_space represent relationships. Rules: Compatibility and availability
conditions decide whether a space can be assigned.

4. Allocation approach

For a request, the program checks candidate spaces in nearest-first order. A candidate must have an available
status and must satisfy the vehicle/requirement compatibility rule. After a match, the program retracts the
available-space fact and asserts an occupied-space fact. This update prevents the same space from being
assigned again during the current program session.

5. Important Prolog concepts

Concept          Use in this project
Domains          Declare the data types used by the program.
Database         Store parking-space facts that can be updated.
Facts            Describe parking spaces and candidate ordering.
Rules            Check compatibility and find suitable spaces.
Retract          Remove the old available-space fact.
Assertz          Insert the updated occupied-space fact (if supported by the lab compiler).
Cut (!)          Commit to the first suitable candidate after allocation.

6. Test cases

Test 1:    car + regular → P9 (compact, distance 1).
Test 2:    car + accessible → P6 (accessible, distance 2).
Test 3:    suv + large → P8 (large, distance 4).

7. Limitations and compiler check

This source follows the classic Turbo Prolog section layout. Turbo Prolog versions and lab-compatible compilers
may differ in built-in database and input predicates. Verify assertz, retract and readln in the exact compiler
used for the practical. Candidate facts are manually ordered by distance; update the order if distances change.
Accessibility is applied when a vehicle requests an accessible space; the program does not implement a separate
waiting queue that reorders arriving vehicles.

8. Conclusion

The project demonstrates rule-based reasoning, constraint checking, nearest-first selection and dynamic database
updates in a parking allocation problem.
